# Prompt สำหรับ Claude Code — จัดโปรเจกต์ + เริ่ม Phase B

> วิธีใช้:
> 1. วางไฟล์ทั้ง 3 (CLAUDE.md, PROJECT_SPEC.md, PHASE_B_EXECUTION_PLAN.md) ในโฟลเดอร์โปรเจกต์ก่อน
>    - `CLAUDE.md` → วางที่ root
>    - อีก 2 ไฟล์ → วางใน `docs/`
> 2. เปิด Claude Code ในโฟลเดอร์นั้น
> 3. ก๊อป prompt ด้านล่างวางทีละบล็อก (อย่าเทหมดทีเดียว)

---

## STEP 0 — ให้มันสำรวจ + จัดบ้านก่อน

```
อ่าน CLAUDE.md และไฟล์ใน docs/ ให้เข้าใจภาพรวมโปรเจกต์ก่อน

จากนั้นช่วยทำ 3 อย่าง (ทำทีละอย่าง รายงานให้ฉันดูก่อนลงมือจริงทุกครั้ง):

1. สำรวจโครงสร้างโปรเจกต์ปัจจุบันทั้งหมด แล้วสรุปให้ฟังว่ามีไฟล์อะไรบ้าง อันไหนคือของ Phase A ที่ใช้งานจริง อันไหนที่ดูเหมือนไฟล์ทดลอง/ซ้ำ/ไม่ได้ใช้แล้ว

2. เสนอ (ยังไม่ต้องลบ) รายการไฟล์ที่ควรลบหรือรวม พร้อมเหตุผลทีละอัน ให้ฉันเห็นก่อน — ฉันจะเป็นคนบอกว่าอันไหนลบได้ อันไหนเก็บ

3. เสนอโครงสร้างโฟลเดอร์ใหม่ที่รวม Phase A + Phase B เป็นโปรเจกต์เดียวให้เป็นระเบียบ

ห้ามลบหรือย้ายไฟล์ใดๆ จนกว่าฉันจะอนุมัติเป็นรายการ
```

> ⚠️ ทำไมต้องให้มันเสนอก่อนลบ: การลบไฟล์เป็น action ที่ย้อนกลับยาก ให้มันโชว์รายการก่อนเสมอ แล้วเราตัดสินใจเอง (โดยเฉพาะไฟล์ที่ไม่แน่ใจ อาจมีอะไรสำคัญซ่อนอยู่)

## STEP 2 — เริ่ม Phase B (หลังบ้านเรียบร้อย)

```
ตอนนี้เริ่ม Phase B ตาม docs/PHASE_B_EXECUTION_PLAN.md

เริ่มที่ STAGE 1 ก่อน: เตรียม dataset
- เขียนสคริปต์ bulk-generate: ดึง arXiv ~500 ใบ (cs.CL + cs.AI, ผสมใหม่+เก่า) → ส่งเข้า Gemini → ได้การ์ดไทย JSON
- reuse โค้ดดึง arXiv + เรียก Gemini จาก Phase A ถ้ามีอยู่แล้ว อย่าเขียนซ้ำ
- ใส่หน่วงเวลา 4-5 วิ/ใบ + retry backoff (โควต้า Gemini 500/วัน, 15 RPM)
- อย่าเพิ่งยิง batch 500 — ทดสอบกับ 5-10 ใบก่อน โชว์ผลให้ฉันตรวจโทนภาษาไทย

ยังไม่ต้องทำ stage อื่น รอฉันโอเค stage 1 ก่อน
```

> Stage ต่อๆ ไป (เทรน/eval/GGUF/serve) ส่วนใหญ่ทำบน Colab ไม่ใช่ใน Claude Code — พอถึงตอนนั้นค่อยเอา notebook มาถามใน chat แยก

## 💡 คำแนะนำวิธีทำงานกับ Claude Code ให้ดีขึ้น

รวบจากที่เจอบ่อย เอาไปใช้ได้เลย:

**1. ใช้ plan mode ก่อนงานใหญ่**
กด Shift+Tab เพื่อสลับเป็น plan mode — มันจะวางแผนให้ดูก่อนโดยยังไม่แก้โค้ด เหมาะกับงานที่กระทบหลายไฟล์ (เช่น STEP 0) พอ plan โอเคค่อยให้ลงมือ

**2. อัปเดต CLAUDE.md เรื่อยๆ**
ท้าย CLAUDE.md มีช่อง "สถานะปัจจุบัน" — พอทำ step ไหนเสร็จ บอกมันว่า "อัปเดตสถานะใน CLAUDE.md ด้วย" เพื่อให้ครั้งต่อไปที่เปิดมา มันรู้ว่าทำถึงไหน (กันมันลืม context)

**3. ให้ commit บ่อย = safety net**
ทุกครั้งที่ได้ของที่ใช้ได้ บอก "commit ก่อน" — ถ้า step ต่อไปพัง ย้อนกลับได้ ไม่เสียงานทั้งหมด

**4. เวลามันทำเยอะเกินสั่ง ให้หยุดทันที**
ถ้าเริ่มเห็นมันแก้ไฟล์ที่ไม่เกี่ยว บอก "หยุดก่อน ขอโฟกัสแค่ [สิ่งที่สั่ง]" — อย่าปล่อยให้มันไหลไปไกล

**5. งานที่ย้อนยากให้มันถามก่อนเสมอ**
ลบไฟล์ / เปลี่ยน schema DB / แก้ .env / ลบตาราง — พวกนี้บอกมันไว้ว่า "ก่อนทำอะไรที่ย้อนกลับยาก ให้ถามฉันก่อน"

**6. อย่าให้มันเดา secret/key**
ถ้าต้องใช้ API key ให้ใส่ใน .env เอง อย่าให้มันฮาร์ดโค้ดลงไฟล์ (แล้วเผลอ commit)

**7. บอก context ที่มันมองไม่เห็น**
เช่น "โควต้า Gemini จริงของฉันคือ 500/วัน ไม่ใช่ 1,500 ตามใน docs ทั่วไป" — มันไม่รู้ของจริงถ้าเราไม่บอก

## สรุปลำดับ

```
วางไฟล์ → STEP 0 (สำรวจ+เสนอ) → ตรวจ → STEP 1 (จัดบ้าน+commit) → STEP 2 (Phase B stage 1) → ...
```

ค่อยๆ ไปทีละ step ครับ ไม่รีบ — ของที่ทำเร็วเกินมักพังแล้วแก้นานกว่า
